# 土地価格と取引価格を分け、取引価格は物件種別ごとに表示する

- 日付: 2026-09-14
- 状態: 一部置換済み（取引価格の前年比の除外は[ADR 0013](0013-transaction-year-comparison.md)で置換）
- 関連: [ADR 0011](0011-unified-land-prices.md)の画面のデータ選択を一部置換。土地価格の統合・照合方針は継続。

## 背景

土地価格は公示地価と基準地価に基づく評価価格であり、実際に売買された価格とは性質が異なる。既存の画面では「土地価格」と「マンション取引価格」を同列に置き、取引APIの種類コードをマンションに固定していた。このまま土地の取引を追加すると、評価価格と取引価格の区別、取引種別ごとの単価の意味が伝わりにくい。

## 決定と理由

最上位の選択を「土地価格」「取引価格」にする。取引価格を選ぶと、その中で「中古マンション等」「宅地（土地）」「宅地（土地と建物）」を一つ選べるようにする。初回は従来の中古マンション等を表示し、その後の種別選択は土地価格との往復でも保持する。年の対応範囲、土地価格の用途フィルター、前年比・地点履歴の対応範囲は従来どおりとする。

XPT001の不動産取引価格情報を使い、選んだ種類コードだけを要求する。農地・林地および成約価格情報は今回の対象に含めない。取得パイプラインを共通化し、種別の定義・表示名・種類コード・単価の説明は[transactions.ts](../src/transactions.ts)にまとめる。種別を指定しない既存APIクライアントは従来どおりマンションとして扱う。

APIが返す位置は物件所在地ではなく最寄り駅であるため、種別内で同じ駅座標の㎡単価の中央値を表示する。地図・ランキング・詳細・範囲の中央値はすべて同じ集計結果を使う。公表済みの㎡単価を優先し、ない場合は正の取引総額と正の面積から計算する。「以上」などの値は総額からの計算に使わず、公表された有効な㎡単価がある場合はその値を使う。

中古マンション等は専有面積、宅地は土地面積あたりの単価になる。「宅地（土地と建物）」には建物価格も含むことを選択肢・指標説明・詳細に明記し、土地のみの価格として解釈させない。種別間で価格の意味が異なるため、混合集計を行わない。集計キーと地点IDも種別で区別し、種別変更時は地点の選択を解除する。

取引種別をブラウザのクエリキーとAPIのURLに含め、取得・先読み・キャンセル・再試行を同じキーで扱う。サーバーは元APIの種類コードを含むURLで保存する既存の方式を維持する。これにより別種別のキャッシュの混入を防ぎ、取得済みの種別に戻るときは既存データを再利用できる。土地価格のキャッシュキーや照合処理は変えない。

## 代替案とトレードオフ

- 種別を最上位に並べると、土地価格と実取引の関係が曖昧になるため、取引価格の中に置く。
- 全種別を一括取得して画面で絞り込む方法は、見ていない種別まで取得して待ち時間を増やすため採用しない。種別の初回切り替えでは追加取得が発生する。
- 異なる種別をまとめた中央値は単価の意味が混ざるため提供しない。駅の座標が一致しても別の母集団として扱う。
- 土地のみの評価価格と取引価格から差額・騰落率を算出する方法は、観測地点・取引条件・標本の違いを補正できないため採用しない。

## 見直す条件

農地・林地や成約価格が必要になった場合は、面積と価格の意味、提供期間を確認して対象を広げる。種別横断の相場比較や取引価格の時系列が必要になった場合は、標本の変化を考慮した集計設計を別途検討する。
