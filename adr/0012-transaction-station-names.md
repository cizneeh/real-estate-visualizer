# 取引の駅座標を国交省の駅データと照合して駅名を表示する

- 日付: 2026-09-14
- 状態: 採用

## 背景

取引価格のXPT001は物件の最寄り駅の座標を返すが、駅名を返さない。同じ座標の取引をまとめる際、先頭の取引の市区町村名から「国立市の駅周辺」のような見出しを作っていた。同じ駅を最寄りとする取引には複数の市区町村が含まれるため、集計地点を識別できず、対象範囲も誤解しやすい。

## 決定と理由

取引のあるタイルについて、同じ国交省のXKT015（駅別乗降客数）の駅名と駅形状を取得する。取引の駅座標から駅の線分までの距離で照合し、「国立駅周辺」のように詳細・ランキングへ表示する。同じ名称の路線別形状は一つの候補にまとめ、遠すぎる候補や異なる駅名が同程度に近い場合は駅名を推測しない。距離による照合であり、APIが取引に対して駅名を直接保証するものではない。

駅データは年に依存しないURLで既存の取得制御・サーバーキャッシュを再利用する。取引のないタイルや地価だけの取得では追加要求しない。ブラウザのHTTPキャッシュは価格と駅データの両方の鮮度を超えないようにする。駅データの取得失敗時も取得済みの価格は返し、駅名は「駅名不明」とする。この応答はHTTPキャッシュに保存しない。

価格の中央値と件数は従来どおり座標単位で集計する。市区町村の補足表示には集計対象に含まれる市区町村をすべて列挙する。

## 代替案とトレードオフ

背景地図の駅名を使う方法は、ズームやタイルの読み込み状態で得られる候補が変わる。主要駅の固定リストは全国を網羅しない。全国の鉄道データの同梱は追加通信を省けるが、配布データと更新運用を増やす。今回は既存の国交省APIとキャッシュを利用する。

駅データが未取得の場合は追加の通信と待ち時間が発生する。APIの提供時点の違い、新駅・廃駅・改称、タイル境界や近接する別名の駅では対応が取れない場合がある。過去年も取得時点の駅データで照合し、取引当時の名称を復元しない。照合できない場合も価格の座標や集計対象は変更しない。

## 見直す条件

取引APIが駅名や対応する駅コードを返すようになれば直接利用する。駅名不明・誤照合が増える場合は駅データの対応年と照合条件を確認する。追加取得が待ち時間やAPI制限に影響する場合は、取得と表示の分離や駅データの配布方式を見直す。具体的な距離条件は[実装](../server/stations.ts)を参照する。
