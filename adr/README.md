## 記録する内容

各ADRには、日付と状態に加え、次の内容を判断の規模に応じて簡潔に書く。

- 背景となる問題・制約。
- 採用する方針と、その理由。
- 主な代替案を採用しない理由と、受け入れる不利益。
- 判断を見直す条件。
- 関連する実装・検証・外部仕様へのリンク。

リクエスト間隔、並列数、キャッシュの有効期間、取得枚数などの調整値は原則として転記しない。「何を制限するのか」「なぜ制限するのか」「何を見て調整するのか」を残し、現在の値は実装を参照する。外部APIの仕様と、このアプリで選んだ制御方針は区別する。

## 更新方法

運用ルールは[AGENTS.md](../AGENTS.md)に置く。ファイル名は`連番-短い英語名.md`とし、追加時にこの一覧も更新する。

既存の判断を変更する場合は新しいADRを作り、旧ADRを「置換済み」にして双方をリンクする。過去の理由は残す。誤記の修正・補足・リンク更新は既存ADRに反映してよい。設計方針が同じまま調整値だけを変える場合は、ADRの追加・更新を必須にしない。
