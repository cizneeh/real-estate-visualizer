# Geoloniaの住所データで検索し、位置精度に応じて地図を移動する

- 日付: 2026-09-10
- 状態: 採用

## 背景

地図を手動で移動する方法と現在地取得だけでは、離れた住所の周辺を探すのに手間がかかる。日本国内の住所を入力して周辺の価格を確認したい。現行のMapLibreとOpenFreeMapを継続利用し、追加の有料API契約やAPIキーを必要としない構成にする。

## 決定と理由

`@geolonia/normalize-japanese-addresses`を検索時に遅延ロードし、Geoloniaが配信する住所データから座標を取得する。検索ボタンまたはEnterで明示的に検索する。ブラウザから必要な地域のデータを取得し、住所そのものをアプリのサーバーや永続ストレージに保存しない。

正規化できた住所の階層と、返された座標の精度は別の値である。`point.level`を使って結果のラベル・説明・ズームを決める。番地が読み取れても町丁目の代表点しか得られなければ、番地の位置として表示しない。市区町村・都道府県だけの座標は役場・県庁の位置と表示する。地図の出典表示と説明ダイアログにGeoloniaおよびCC BY 4.0へのリンクを設ける。

検索入力の変更・クリア・現在地への復帰・全国表示で古い検索を無効化し、遅れて届いた結果では移動しない。一定時間で待機を終了し、再検索可能にする。ライブラリは通信中断のAPIを提供しないため、無効化した検索の通信自体は完了まで継続する場合がある。

[ADR 0003](0003-location-independent-initial-view.md)の初期表示方針を維持しつつ、住所検索・全国表示を明示的に操作した後は待機中の現在地取得を無効化する。後から現在地が返っても操作済みの地図を上書きしない。現在地ボタンからの再取得は引き続き可能。

## 代替案とトレードオフ

Google Geocoding APIは現在の背景地図との利用条件が合わず、Nominatimの公開サービスはアプリ全体の頻度制限や候補検索の制約がある。Geoloniaを採用し、日本の住所の表記ゆれに対応する一方、施設名検索や全国すべての番地の特定は提供しない。

外部の無料配信の可用性とデータの整備状況に依存する。初回は地域データの取得に時間がかかる場合がある。検索失敗と住所の特定失敗を分けて案内し、入力・再試行を妨げない。通信先には取得する地域やアクセス元が伝わる。

## 見直す条件

番地の網羅性、施設名検索、候補一覧、可用性の保証が必要になったときは、配信データの自前ホスティングや別サービスを検討する。検索画角の調整は実装を参照し、代表点と物件そのものを混同させないことを優先する。
