# 街の値段

国土交通省「不動産情報ライブラリ」のデータを、地図・3D・ヒートマップで探索するWebアプリです。全国を対象にしています。初期表示は東京駅周辺です。位置情報を取得できた場合は現在地の周辺へ移動します。

公開先: [real-estate-visualize.echizen.me](https://real-estate-visualize.echizen.me)

## 起動

Node.js 22.12以上（開発・検証環境は24系）を使用します。

```sh
npm install
npm run dev
```

ブラウザで [http://127.0.0.1:5187](http://127.0.0.1:5187) を開きます。HonoのAPIサーバーは127.0.0.1:8787で同時に起動します。

`.env` に `REINFOLIB_API_KEY=発行されたキー` を設定します。既存環境向けに `MLIT_API_KEY`、`REAL_ESTATE_API_KEY`、`API_KEY` も認識します。キー変更後はサーバーを再起動してください。`.env` を上書きする必要はありません。キーはHonoサーバーだけで読み込み、ブラウザには送信しません。`VITE_` の付いた環境変数にキーを設定しないでください。

## 操作

- 公示地価、基準地価、公示地価の前年比、中古マンション等の取引価格を切り替えられます。
- 3D、ポイント、ヒートマップで表示できます。前年比は3Dとポイントに対応しています。
- 公示地価・前年比は1995年、基準地価は1997年、マンション取引は2005年から当年まで選択できます。観測年のメニューで直接選ぶか、横にスクロールできる年表で切り替えます。年度の自動再生もできます。データ種別を切り替えて選択年が提供開始より前になる場合は、最初の対応年に移動します。
- 2005年のマンション取引は7〜12月（第3・第4四半期）のみです。未公表の年度・対象地点のない範囲は空になります。前年比は変動率が提供されている地点だけを表示します。
- 初期表示は東京駅を中心としたズーム13の地図です。位置情報の許可・取得を待つ間も、東京中心部と周辺の価格データを読み込んで探索できます。取得できた場合は現在地の周辺へ移動します。拒否・取得失敗・タイムアウト・非対応・表示範囲外の場合は、初期表示の東京周辺から探索できます。
- 「現在地に戻る」で再取得、「全国を表示」で日本全体に戻れます。地図の移動・縮小は日本周辺の範囲に制限しています。現在地が表示範囲外の場合は、日本国内の地域を選ぶ案内を表示します。
- 点・柱・ランキングをクリックすると、その地点の詳細を確認できます。
- スマートフォン幅では左上のボタンからデータ選択パネルを開きます。
- スマートフォンでは「色と高さの見方」（ポイント・ヒートでは「色の見方」）から凡例を開閉できます。初期状態では折りたたんで地図の表示領域を確保します。
- 地点の詳細はスマートフォン向けに文字・余白を詰めて表示します。続きがある場合は下端にスクロール案内が出て、タップでも続きを確認できます。閉じるボタンはスクロール中も固定されます。

## データの意味

| 表示 | API | 集計・表示 |
| --- | --- | --- |
| 公示地価・前年比 | XPT002 / priceClassification=0 | 各年1月1日の土地価格（円/㎡）と対前年変動率 |
| 基準地価 | XPT002 / priceClassification=1 | 各年7月1日の土地価格（円/㎡） |
| マンション取引 | XPT001 / priceClassification=01 / landTypeCode=07 | 中古マンション等の取引情報。取引ごとの㎡単価を算出し、最寄り駅座標ごとに中央値を表示 |

取引価格APIの位置は**物件そのものではなく最寄り駅**です。面積が「以上」「未満」等の値は単価計算から除きます。集計は表示範囲内の取得済みデータが対象で、地域全体の相場推計ではありません。土地の価格とマンションの価格は直接比較できません。

3Dの高さは価格の平方根×0.9（上限6,500m）で視認性を調整しています。前年比では絶対値×95＋80で高さを表示し、色で増減を区別します。これは建物の高さではありません。ヒートマップは価格で重み付けした密度なので、地点数の影響も受けます。

北海道から沖縄・離島を含む全国のデータに対応しています。取得範囲は日本を含む経度122〜154・緯度20〜46に絞ります。APIが対応するズーム13のタイルが160枚を超える広域表示では取得せず、拡大を促す案内を表示します。

現在地はブラウザのGeolocation APIで取得します（HTTPSまたはlocalhostが必要）。取得は初回と現在地ボタン操作時のみで、追跡・永続保存はしません。初期表示の東京周辺、または移動後の表示範囲と、先読みする周辺タイルの座標が価格APIへ送られます。

価格データは年度・データ種別・ズーム13のタイル単位で取得します。ブラウザではTanStack Queryを使い、30分間は取得済みデータを再利用します。使われなくなったキャッシュは1時間後に破棄され、このメモリキャッシュはページのリロードで消えますが、新鮮な成功応答はブラウザのHTTPキャッシュでも再利用します（価格ありは最大5分、空は最大1分。元データの残りの有効期間を超えません）。公示地価と前年比、先読みと通常表示は同じURLを使います。空のタイルもキャッシュします。

移動・ズーム終了後、必要なタイルの組み合わせが200ms安定したら、未取得・期限切れのタイルを取得します。取得済みデータはすぐ表示し、新しく届いた分から地図・集計を更新します。集計途中は地点数と進捗を表示します。表示範囲内の取得完了後、400ms待って外周1タイル（最大32枚）を先読みします。先読みした画面外の地点は、表示範囲の集計に含めません。

ブラウザからの通信は最大6件、うち先読みは最大2件を並列実行します。国交省APIへの通信は最大4件、うち先読みは最大2件を並列実行し、開始間隔は200ms以上に保ちます。前の応答の完了を待たずに次を開始します。待ち行列では表示範囲内を優先し、不要になった取得はキャンセルします。

サーバーでは同じタイルの同時リクエストをまとめ、メモリ・ディスクキャッシュ（`.cache/tiles`）を使います。メモリは最近使った最大300タイルを保持します。一部の取得に失敗しても成功した地点は表示し、再試行では失敗したタイルだけを取得します。429応答時は少なくとも30秒（`Retry-After`が長ければその時間）、その他の取得エラー時は少なくとも5秒、外部APIの新しい取得を抑制します。ブラウザの自動再試行はサーバーエラーに対して最大1回で、認証エラー・429では行いません。

価格キャッシュの期限は[server/cachePolicy.ts](server/cachePolicy.ts)にまとめています。本番の共有エッジキャッシュとローカル版で同じ判定を使います。

| 結果 | 再取得せず使う期間 | 期限後に以前の結果を表示しながら更新できる期間 |
| --- | --- | --- |
| 取得時のUTC暦年より古い公示地価・基準地価（価格あり） | 90日 | 最大1日 |
| 当年の公示地価・基準地価、全年度の取引価格（価格あり） | 1日 | 最大1日 |
| 空の結果 | 1時間 | なし（再取得の完了を待つ） |

これはアプリ側の設定です。Cache APIのTTLは保存保証ではなく、期限前にキャッシュが消える場合もあります。背景更新に失敗しても元の取得日時と期限を維持し、成功後は次の取得から新しい結果を使います。画面へのプッシュ通知・定期ポーリングは行いません。新しい年度は別のキーになり、既存年度のキャッシュに妨げられません。訂正は次の取得・更新まで反映が遅れる場合があります。

`/api/tiles/*`の`X-Price-Cache`は`MISS`（取得）、`HIT`（再利用）、`STALE`（以前の結果を返して背景更新）です。`STALE`は本文にも`stale: true`を返し、HTTPキャッシュには保存しません。エラー、ヘルスチェック、一括範囲APIも`no-store`です。ブラウザのキャッシュを持たない別利用者でも、同じエッジ拠点に保存済みなら再利用できます。

## 構成

React + TypeScript + Vite / TanStack Query / Hono + Node.js / MapLibre GL JS 6 / Biome。

- `src/App.tsx`: 画面、条件選択
- `src/PointDetails.tsx`: 地点の詳細、スクロール操作と続きの案内
- `src/usePriceTiles.ts`: 表示範囲のタイル取得、段階表示、周辺先読み
- `src/tileQueries.ts`: TanStack Queryのキー・キャッシュ・再試行設定
- `src/tiles.ts`: タイル座標・表示範囲・周辺タイルの計算
- `src/requestQueue.ts`: 同時実行数・優先順位・開始間隔の制御
- `src/MapCanvas.tsx`: 背景地図、点・柱・ヒートマップ、現在地マーカー
- `src/mapStyle.ts`: 背景地図の配色と日本語ラベル
- `src/useCurrentLocation.ts`: 現在地の取得・再試行・エラー処理
- `src/metrics.ts`: 表示用の集計・単位・色
- `server/app.ts`: タイル単位API、入力チェック、データ正規化（旧範囲APIも維持）
- `server/tileStore.ts`: サーバーキャッシュ、並列取得、共有リクエストのキャンセル管理
- `server/data.ts`: 国交省の形式からのデータ正規化

MapLibre 6のWorkerはViteの`?worker&url`で独立したファイルにバンドルします。本番ビルドでも地図を描画できる構成です。

背景地図はOpenFreeMapを利用し、日本語ラベルで表示します。ダークスタイルをベースに、陸地・水域・道路・建物・地名を識別しやすい配色に調整しています。背景地図・フォントと国交省APIへのネットワーク接続が必要です。Node.jsの開発サーバーはローカルホストに限定しています。Workersでは同じドメインに画面とAPIを公開します。利用者認証はありません。

## Cloudflareへの公開

`main`に取り込まれたコミットをビルドし、Cloudflare Workersに公開します。画面はStatic Assets、`/api/*`はHonoが処理します。

```sh
npm ci
npx wrangler login
npx wrangler secret put REINFOLIB_API_KEY
npm run deploy
```

APIキーはCloudflareのSecretに保存します。ブラウザのビルドやGitには含めません。独自ドメイン・アカウント・Worker名は`wrangler.jsonc`で管理します。`npm run build`でWorkers用の環境変数の型も生成します。

本番相当のローカル確認には、`.dev.vars`に`REINFOLIB_API_KEY`を設定して`npm run cf:dev`を実行し、http://127.0.0.1:8790 を開きます。設定とバンドルだけを確認する場合は、ビルド後に`npx wrangler deploy --dry-run`を実行します。

上のファイルキャッシュと取得中リクエストの共有はNode.jsでの動作です。Workersはファイルキャッシュを使わず、Cache APIに正常なタイルを一時保存します。キャッシュはデータセンターごとで、取得数・開始間隔・エラー後の待機の制御はisolate内です。異なるリクエスト間で取得中のPromiseは共有しません。ブラウザでの段階表示・先読み・キャッシュは共通です。D1への永続保存は未導入です。公開構成は[ADR 0004](adr/0004-cloudflare-deployment.md)、共有キャッシュとAPI継続利用の判断は[ADR 0008](adr/0008-shared-price-cache.md)に記録しています。

対応ブラウザではWebMCPの`read_visible_prices`から表示中のデータを読み出せます。非対応ブラウザでは通常のUIだけで利用できます。
今回の検証環境のChromeにはWebMCP APIがないため、ネイティブのツール登録・実行は未検証です。

## 検証・本番ビルド

```sh
npm run lint
npm test
npm run test:e2e:cache
npm run test:e2e:shared-cache
npm run test:e2e:history
npm run test:e2e
npm run build
```

E2Eテストは開発サーバー起動中に実行します。`test:e2e:cache`は価格APIを模擬し、段階表示・ズーム／移動時のキャッシュ再利用・先読み・年度切り替え・キャンセル・部分失敗の再試行を検証します。`test:e2e`は実APIで画面全体を確認します。どちらもインストール済みのGoogle Chromeを使い、スクリーンショットをプロジェクト内の`tmp/screenshots/`に保存します。

`test:e2e:history`は価格APIを模擬し、過去の年の選択・種別ごとの開始年・自動再生の折り返し・デスクトップとスマートフォン幅での年表操作を検証します。

ビルドした画面をHonoから配信する場合は開発サーバーを停止後、`npm start`を実行し、http://127.0.0.1:8787 を開きます。

`.env`、APIキャッシュ、スクリーンショット、依存パッケージはGit管理対象外です。`.env.example`にキーの雛形だけを含めています。
